# 换机复现：完整操作手册（备份 → 新机器恢复）

> 目标：当前这台电脑坏了，换一台新电脑，能还原出**一模一样**的 ERPNext-MCP 项目环境。
>
> 前提：你已经跑过一次 `erp/backup.sh`，拿到了一个 `erpnext-backup-*.tar.gz` 备份文件，并存到了本机之外。

---

## 总览：要还原的东西分两层

| 层 | 内容 | 存放位置 | 换机怎么拿 |
|---|---|---|---|
| ① 代码 | server/、docs/、erp/ 脚本 | GitHub 私有仓库 | `git clone` |
| ② 数据+配置 | 数据库、站点文件、`.env` | 本机 Docker 卷 | 备份 tar.gz 恢复 |

**缺一不可**：只有代码没数据 = 空系统；只有数据没代码 = 有库没 MCP server。

---

## 第一步（旧电脑，坏之前就要做）：跑备份

```bash
cd /d/second
bash erp/backup.sh
```

会生成 `backups/erpnext-backup-<时间戳>.tar.gz`。**把它拷到移动硬盘/网盘/新电脑**——这是换机的命根子。

> 建议：每次数据有变动（新建客户、下订单）就重跑一次，保持备份新鲜。

---

## 第二步（新电脑）：装前置

1. **Git**（clone 代码用）
2. **Docker Desktop**，装完要在 Settings → Resources → Proxies 里配好代理（否则镜像拉不动，本机同款坑）
3. **Node.js ≥ 18**（跑 MCP server 用，零依赖，不需要 npm install）
4. Git Bash（Windows 自带，跑脚本用）

---

## 第三步：clone 代码 + 拿备份

```bash
git clone https://github.com/ethafleischaker3-eng/erpnext-mcp.git
cd erpnext-mcp
```

把备份文件放进项目目录：

```bash
mkdir -p backups
cp /某处/erpnext-backup-*.tar.gz backups/
```

---

## 第四步：解出备份内容

```bash
cd /d/second   # 项目根目录
mkdir -p restore
tar -xzf backups/erpnext-backup-*.tar.gz -C restore
```

解出来应该是这几个文件：

```
restore/
  snapshot.sql     # 数据库 SQL（可读副本）
  sites.tar.gz     # 站点卷（sites：含 site_config.json、加密钥）
  db-data.tar.gz   # 数据库卷（MariaDB 数据目录）
  env.backup       # .env（ERPNEXT_VERSION / DB 密码 / 站点名 / 端口）
  manifest.txt     # 备份时记录的信息
```

---

## 第五步：恢复 .env 并起服务

```bash
cp restore/env.backup frappe_docker/.env

cd frappe_docker
docker compose -f compose.yaml \
  -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml \
  -f overrides/compose.noproxy.yaml up -d
```

首次会自动 `docker pull` 镜像（走代理）。等容器起来，看数据库健康：

```bash
docker ps   # frappe_docker-db-1 状态应为 Up (healthy)
```

---

## 第六步：恢复数据（两条路，二选一）

> 说明：因为站点名固定 `erpnext.local`、库名固定 `_ebde57cb5cf2199a`、compose 文件相同，理论上卷名也会一致，可整卷还原。SQL 是更稳的兜底。

### 路线 A：SQL 导入（推荐，最稳）

新环境刚起，库里已经有空的同名库，直接覆盖导入：

```bash
docker exec -i frappe_docker-db-1 mariadb -uroot -perpnext-dev-123 \
  _ebde57cb5cf2199a < restore/snapshot.sql
```

> 前提：`sites.tar.gz` 里的 `site_config.json`（站点密钥）也得对得上。若两步都走，密钥用卷里的，数据用 SQL 的，见下。

### 路线 B：整卷还原（连站点密钥一起）

> Windows Git Bash 下先关闭 MSYS 路径转换，否则容器内 `/data` 会被误转成 Windows 路径导致失败：
> ```bash
> export MSYS_NO_PATHCONV=1
> ```

```bash
# 回到项目根（restore/ 解压在这里）
cd /d/second

# 先停服务
cd frappe_docker
docker compose -f compose.yaml -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml -f overrides/compose.noproxy.yaml down
cd ..

# 还原 db-data 卷（数据从宿主机文件经 stdin 灌入容器，绕开 Windows bind-mount 路径坑）
DB_VOL="$(docker volume ls --format '{{.Name}}' | grep -E '(^|_)db-data$' | head -1)"
docker run --rm -i -v "$DB_VOL":/data alpine tar xzf - -C /data < restore/db-data.tar.gz

# 还原 sites 卷
SITES_VOL="$(docker volume ls --format '{{.Name}}' | grep -E '(^|_)sites$' | head -1)"
docker run --rm -i -v "$SITES_VOL":/data alpine tar xzf - -C /data < restore/sites.tar.gz

# 重新起
cd frappe_docker
docker compose -f compose.yaml -f overrides/compose.mariadb.yaml \
  -f overrides/compose.redis.yaml -f overrides/compose.noproxy.yaml up -d
```

---

## 第七步：重建 mcp-service 账号（必须！）

数据库虽然还原了，但 `mcp-service` 的 API token 是部署时写进容器 `/tmp/mcp_token.txt` 的，**不在数据库里**。换机后必须重新生成：

```bash
docker cp erp/replay-e01.py frappe_docker-backend-1:/tmp/replay-e01.py
docker exec -w /home/frappe/frappe-bench/sites frappe_docker-backend-1 \
  /home/frappe/frappe-bench/env/bin/python /tmp/replay-e01.py
```

末尾看到 `[verify] 结论：PASS` 即成功。脚本会把新 token 写到容器内 `/tmp/mcp_token.txt`，并重建 `MCP Business Caller` 角色和 23 个 DocPerm。

---

## 第八步：拿到新 token 给 MCP server 用

```bash
docker exec frappe_docker-backend-1 cat /tmp/mcp_token.txt
```

输出形如 `token xxxx:yyyy`。把它填进 MCP 客户端配置（Claude Code 的 `mcpServers`）：

```json
{
  "mcpServers": {
    "erpnext": {
      "command": "node",
      "args": ["d:/second/server/index.js"],
      "env": {
        "ERP_BASE_URL": "http://localhost:8080",
        "ERP_API_KEY": "<xxxx>",
        "ERP_API_SECRET": "<yyyy>"
      }
    }
  }
}
```

---

## 第九步：验证

1. 浏览器开 `http://localhost:8080`，能登进 ERPNext，客户列表能查到原来的数据。
2. 起 MCP server，跑一下 server 自检：

```bash
cd /d/second/server
node test/selftest.js
```

3. 让 Claude Code 查一下客户（`erpnext_customer_search`），能返回之前的客户即复现成功。

## 常见坑

| 现象 | 原因 | 解法 |
|---|---|---|
| `docker pull` 卡住/超时 | 没配代理 | Docker Desktop Settings → Proxies 配代理 |
| 起服务后 db 一直不 healthy | DB 卷损坏 | 走路线 A 用 SQL 重灌 |
| 登录 ERPNext 报 site 不存在 | sites 卷没还原 | 检查路线 B 的 sites 还原步骤 |
| MCP 调后端 401/403 | token 没重建 | 重跑第七步 replay-e01.py |
| 后端返回「不可达」 | ERP_BASE_URL 错 / 后端没起 | 检查 8080 端口和 env |

---

## 一句话总结

**旧电脑：`erp/backup.sh` 出 tar.gz 存起来。新电脑：clone 代码 → 起 Docker → 还原数据 → replay-e01 → 换 token。** 全流程依赖三样东西：GitHub 仓库、备份 tar.gz、这台电脑能翻墙跑 Docker。
