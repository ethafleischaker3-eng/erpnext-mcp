## 变更原因与证据

1. 上游规范 §7.3 要求客户端能力核查在后端侧准备之后、tool 开发之前完成；原总则仅要求其先于正式 L3 验收。
2. PRD 原文同时保留全自动草稿写入并声明整体降为 L2，与上游规范 §3.2、§7.3 冲突。
3. PRD 的“同一调用上下文”幂等边界缺少目标客户端、SDK 与传输方式的可实现性证据。
4. 盲出题、tool 契约和覆盖映射需要拆分，保证先出题、实施隔离与每个写 tool 覆盖要求同时成立。
5. 封闭任务包缺少明确 Owner、Implementer、写入集所有权及统一 Evidence Manifest。
6. 总则尚未满足自身投入使用的完成定义。
7. 总则完成定义要求 B00/A01 先冻结，形成治理文件与任务包之间的循环依赖。
8. 登记表使用未定义的“待创建”状态，并聚合登记 E/F 任务包。
9. 批次访问隔离缺少可信且跨会话稳定的调用方身份模型。

## 变更内容

- 新增 B00 后端基础能力准备，并将其设为 A01 的强制前置。
- 将 A01 设为任何正式业务 tool 开发的前置门槛，仅允许隔离确认能力探针例外。
- 新增 B05 幂等可实现性调研，结论形成前阻断 E02。
- 将 C01 拆为 C01a 盲出题与 C01b 覆盖映射、补题、可解性验证及最终冻结。
- PRD 统一规定：客户端核查不通过时，所有写操作只能返回 plan，不保留全自动写入。
- 总则增加 Owner、Implementer、Reviewer、Acceptor、写入集所有权和 Evidence Manifest。
- 新建任务包模板、任务包登记表、实施区与验收区边界、变更记录模板和退回记录模板。
- PRD 状态转为“待复评”，总则保持“待评审”。
- 消除总则冻结循环：总则 v1 与模板先冻结，B00/A01 改为后续任务启动门槛。
- 增加“规划中”状态，并将尚未建立文件的登记项统一标为规划中。
- 将 E01-E05、F01-F05 拆分为独立登记行。
- 将可信调用方身份基础纳入 B00，将批次 Owner 持久化、跨会话授权与查询契约纳入 E04。
- 修正 PRD 边界处理表残留的旧降级口径。
- 修正 PRD 合成验收数据对决议编号的引用：决议 6 改为决议 7。
- 修正“草拟”状态进入条件，使其与“规划中”状态及后续流转规则一致。
- 明确 B00 仅承担权限可行性与临时探针权限，E01 承担冻结契约下的正式业务权限；禁止直接沿用临时权限。
- 将验收拆为 L3 与 L2 受限形态两套矩阵，L2 强制断言 plan 正确且数据库零写入。
- 暂停不可证明的“跨调用上下文同参数必定新建”幂等结论，新增 B05 证据与决策要求，并补全有效指纹字段。
- 补齐 Customer/Supplier/Item create/update 与 Item Price set 的回滚路径、前镜像和版本保护。
- 将各类 confirm 的状态漂移与乐观并发断言写开，要求 B01-B04 实测后端原子保证。
- 增加销售、采购完整多步验收题要求，补充对象选择/Link/子表边界与 Contact/Address 非范围声明。
- 补充成功率分母、轮次、重置顺序、调用上限、版本固定和报告复算口径。
- 将具体币种与默认 selling Price List 作为 B00 必须取得并写回 PRD 的冻结事实。
- 修正财务/制造二期范围的决议交叉引用：决议 5 改为决议 6。
- 拆开 confirm/cancel 的幂等状态断言：confirm 合法前态为草稿，cancel 合法前态为已生效。
- 为主数据 update、既有价格修改和 cancel 增加预期版本、状态漂移及同事务/等价原子校验要求。
- 封闭环境无效项排除分母的漏洞：正式轮次必须最终执行全部冻结任务，未补跑环境无效题时不得形成验收结论。
- 将幂等窗口期的 24h/1h 明确为 B05 调研初始假设，不构成 PRD 冻结契约；需求口径与下游实现契约分层冻结。
- PRD 以 `2026-09-12-r1` 作为需求基线重新冻结；A01、B00/B01～B05、C01b 等仍作为下游门槛，不代表 L3、实现或项目验收通过。
- 修正总则残留的“同一上下文”幂等口径，统一由 B05 冻结“同一业务意图”判定规则。
- 增加强制角色隔离、退回/待澄清恢复流转、登记表结构冻结与任务行受控更新规则。
- 新增 P00 项目总控包及任务包、Evidence Manifest、变更记录和退回记录的固定存放位置。
- 收紧 C01a 与 D01/D02 的信息边界：依赖只作为启动或完成门槛，不传递隐藏题目和不允许的调研结论。
- 将任务包模板默认状态改为“规划中”，与状态进入条件保持一致。
- 为总则增加 `v1.0-rc1` 版本身份、精确上游基线、评审责任字段及独立 Freeze Manifest 约定。
- 将模板的系统、接口、数据、数据库、依赖安装、运行环境和外部网络权限拆为逐项必填字段，并完整继承总则禁止事项。
- 拆分 Implementation Reviewer 与 Acceptance Reviewer，增加隐藏验收材料污染隔离及禁止间接泄露规则。
- 增加治理生效前探索证据的重新验证/正式采纳规则，B00 必须将接管结果录入自身 Evidence Manifest。
- 将实际隔离路径、Owner、权限验证和隔离证据设为 C01a/C01b/G01 及其他验收材料任务的硬前置。
- 在任务包登记表增加 Acceptance Reviewer 列，使实施评审与验收评审角色均可在总控层追踪。
- 在任务包模板完成定义中增加“输入输出契约及冻结完成定义未被擅自改变”，并修正隐藏材料污染规则的文字错误。
