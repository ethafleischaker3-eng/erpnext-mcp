## 处理结论

**实现缺陷，责任方 F04（#23 `erpnext_stock_transfer_create`），初步归类待 Owner 拍板。**

根因证据链：

1. D02 `tool-contract.md` §6.1 冻结 `stock_entry_type` 为枚举 `material_transfer`（「固定 material_transfer，server 校验，后端不强制，B04 F9」）——此为 **agent 语义枚举**，server 负责校验并落到后端。
2. B04 `interface-facts.md` §2.1 已实测后端 `Stock Entry` 的 `stock_entry_type` 为 **Link → `Stock Entry Type`**，且正确值为 `Material Transfer`（`purpose` 由 `stock_entry_type` 派生为 `Material Transfer`）。
3. `server/src/tools/stock-transfer-create.js` 第 147 行后端写 `doc` 时直接写 `stock_entry_type: 'material_transfer'`（下划线枚举），**未映射为后端 `Material Transfer`**。因后端 Link 校验未强制（B04 F9），该无效值被 200 接受，`purpose` 退化为 `Material Issue`，`to_warehouse` 被丢弃。
4. 后果：`erpnext_stock_transfer_confirm`（#24）前置断言读到草稿缺 `to_warehouse`，报「调拨单缺源/目标仓」，T09 全链路失败。
