## 变更原因与证据

1. 24 个任务包一律按「冻结清单+哈希 → 独立验收 → 封存 + 下游影响记录」同重量推进，低风险包（契约设计、文档汇编）与写业务数据包（F02/F04）仪式相同，效率偏低。
2. 总则 v1.0 §13「C01a 盲出题先于 D01/D02 契约冻结」把不含业务语义的通用件一并卡在盲测之后：D01（公共契约/错误模型）、E02（幂等/断言/台账）本质是通用基础设施，不依赖业务场景，却被串行到 C01a 之后。
3. 原 E01–E05、F01–F05 各为 5 个包，其中若干相邻包目标相近、依赖时机一致，可合并降低包级治理开销。
4. 依据：总则 v1.0 §2.7（编号稳定）、§5（建议基线可拆分/合并）、§12（变更控制）、§13（依赖与并行）。
