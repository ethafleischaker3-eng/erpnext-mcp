## 变更原因与证据

1. C01a 是盲出题（不得读取 PRD 全文、D02 契约、B01–B05 结论），其两条「作废/冲回」候选以「作废发货单（Delivery Note）/作废收货单（Purchase Receipt）→ 库存冲回」为目标，依据 ERPNext 数据模型（docstatus=2 作废）编写。
2. 但 PRD 已决议 #8（冻结）明确：「不新增收货/发货/调拨的 cancel tool；其取消走管理员运维（异常回滚）；业务取消仅 sales_order_cancel / purchase_order_cancel 两个 MCP tool」。D02 冻结的 26 个 tool 中取消类仅有 `#15 sales_order_cancel` 与 `#18 purchase_order_cancel`。
3. 冻结接口事实已预先记录该边界：B03 §2.2 明确「PR cancel 技术上可行（docstatus 1→2、Bin 冲回归零），但不构成 D02 新增 purchase_receipt_cancel tool 依据，PRD §3.3/已决议 #8」；B04 §7.4 明确「调拨无 cancel tool，其取消属异常回滚由管理员运维执行」。
4. 触发 C01b §15 停止条件「候选无法映射到冻结 26 tool」；经 Owner 讨论后，按规范 §12.6「题目描述的业务行为本身不符合后端实际业务语义，此时 MUST 留记录说明原因」走**改题**而非改契约。

## 影响分析

- 是否重新冻结：否。C01a 候选 v1.0 保持封存不动（本变更发生在 C01b 把候选补齐为冻结任务集的过程中，是 C01b 的覆盖映射结论，不改写 C01a 候选文件）。
- 受影响契约/测试：否。不改变 D02 契约、D01 公共契约、PRD 口径、B01–B05 结论；不新增/删除任何 tool；取消能力覆盖仍由 #15/#18 承担。
- 语义变化：「库存冲回」从 agent 验收范围移出——这与 PRD 决议 #8 一致（agent 不可作废发货/收货/调拨，「冲回库存」归管理员运维异常回滚，不进入 L3/L2 agent 能力判定）。原「作废冲回库存」的业务意图不再由 agent 经 MCP 完成。
- 覆盖下限不受影响：取消 tool（#15/#18）各仍 ≥1 题；写 tool、三档位、失败路径五类、销售/采购多步链覆盖完整。

## 评审结论

2026-09-16，Owner gjg 认可「库存冲回不进入 agent 验收范围」定位，批准将两条「作废/冲回」候选重定向为「取消销售订单 / 取消采购订单」（改题，规范 §12.6），不新增 DN/PR/STE cancel tool（维持 PRD 决议 #8）。改题原因随本变更记录与 C01b Evidence Manifest 留痕。
