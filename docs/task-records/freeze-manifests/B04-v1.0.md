## 已知限制

- 合成对象统一使用 `B04-PROBE-` 标识；单据 name 为 naming_series 连续编号（MAT-STE-/MAT-REC-），合成标识经物料承载，每次测试后以 create 返回的 `name` 列表为清理主键删除或快照恢复；已生效单据先 cancel 再 delete，confirm 产生的库存/流水先 cancel 冲回或快照恢复归零；
- Stock Entry / Stock Reconciliation 的 naming_series 具体格式（推测 `MAT-STE-.YYYY.-` / `MAT-REC-.YYYY.-`）待实测确认；
- Stock Entry 的 `stock_entry_type` 与 PRD #23「仓库间调拨」的对应关系待实测，本包以仓库间调拨为准，其余类型不测；
- Stock Entry 源仓库存不足的报错形式（推测 `NegativeStockError`/`ValidationError` 417）与「可用库存」口径待实测；
- 正向库存就位方式待择一（Purchase Receipt confirm 复用 B03 事实，或 Stock Reconciliation confirm 本包对象），均须测试后归零；
- Stock Reconciliation confirm「覆盖库存基线、无确定性回滚」的具体行为待实测；清理风险——SR confirm 写 GL Entry，cancelled 后可能像 B03 F9 一样不可物理删除，SR 相关零残留主清理路径以快照恢复为准，不可依赖 REST DELETE；
- 调拨/盘点无对应 cancel tool（PRD §5.4 / 已决议 #8），后端原生 cancel 仅作清理摸底，不构成 D02 新增 cancel tool 依据；
- confirm 状态漂移、乐观版本断言与原子性的「后端原生强制」程度待实测，ERPNext 可能不做原生强制，此时结论为「须由 MCP server 层实现」，仍属有效产出（PRD §5.2/§5.5）；
- 前置 Item 复用 B01 已冻结主数据接口事实创建，不重复摸底、不得重新验证 B01 已冻结的主数据结论（同名/版本/区间）；
- 回滚汇总仅引用 B01/B02/B03 已冻结事实，不重新验证；
- Implementer/Acceptor 隔离沿用 B00 已建立的隔离事实（受限账户 + NTFS ACL），B04 不重复建设；
- 后端凭据为本地开发默认值，仅限本地验收环境；迁移共享/生产环境必须更换；
- B04 尚未进入实施中。
