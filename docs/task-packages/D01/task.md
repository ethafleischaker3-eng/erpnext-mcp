## 2. 目标

在**不接入 ERPNext、不改变任何数据库状态、不实现任何 tool 代码**的前提下，冻结一份《MCP 公共契约与错误模型》，作为 D02 冻结 26 个业务 tool（PRD §3.3 #1–#26）各自契约的统一基座。该公共契约只规定**所有 tool 共享的契约层**，不含任何具体 tool 的业务语义，必须覆盖并落地以下七项公共口径：

1. **命名与 tool 标识规范**（PRD §3.2 `erpnext_<资源>_<动作>`、规范 §8.2 命名空间与一致性、§8.3 数量与消歧要求）；
2. **公共 schema 规范**（参数结构、嵌套行项目、Link 字段引用表达、返回结构、分页/过滤/截断/详略，规范 §8.4/§8.5）；
3. **annotation 规范**（四个布尔显式声明、对内执法与对外声明分离、旁挂后端「与外部世界交互=否」，规范 §8.1）；
4. **公共错误模型**（错误分类 + 可自纠报错结构 + 各错误类型的统一响应形状，规范 §8.6、PRD §7 边界处理表、B01–B04 接口事实中的错误行为结论）；
5. **幂等边界契约**（B05 §18.3 结论落地为契约口径：窗口期冻结值、指纹规则、误合并策略、confirm/cancel 状态断言，PRD §5.1、规范 §9.3）；
6. **前置断言 / 事后校验 / 批次台账公共口径**（规范 §9.4/§9.5/§9.6、PRD §5.2–§5.4、B01–B04 事务/原子性/乐观版本断言结论）；
7. **窄接口与允许清单边界**（操作/引用允许清单边界、Link 字段目标限制、子表仅作父单据嵌套、最小权限声明，规范 §9.6、PRD §2.3/§5.6）。

产出物为可复核的《公共契约与错误模型》正文（交付物 CD-2，见第 11 节），其内容结构见第 9 节，是任务包 D02 的权威输入（E02 与本包共同对齐 B05 §18.3、保持一致，非上下游）。D01 结论形成前，D02 不得冻结或实施（登记表 D02 行上游依赖）。

### 9.1 公共契约输出结构

《公共契约与错误模型》正文必须逐项包含并可复核：

1. **命名与 tool 标识规范**：命名空间方案（`erpnext_<资源>_<动作>`）、动作后缀语义（create=草稿、confirm=生效、cancel=取消、plan=只出方案，PRD §3.2；search/get/query=读，由 D01 自 PRD §3.3 工具清单归纳）、相近 tool 消歧要求、命名可调项边界（调前缀/后缀不动语义，PRD §3.2/§8.2）；
2. **公共 schema 规范**：输入参数通用形状（必填标识、嵌套行项目结构、Link 字段引用表达——引用值以语义标识表达、由 server 解析为后端标识，不要求 agent 填后端内部标识符）、返回结构通用形状（语义化标识、分页/过滤/截断/详略默认值，规范 §8.4/§8.5）；
3. **annotation 规范**：四布尔显式声明口径、对外声明与对内执法分离、旁挂后端「与外部世界交互=否」、`idempotentHint` 与幂等实现的对应关系（规范 §8.1）；
4. **公共错误模型**：错误分类枚举 + 每种错误的统一响应形状（错误码、可自纠建议字段、是否透出后端原生信息边界）——覆盖前置断言失败、幂等命中、越权、并发冲突（TimestampMismatchError 417 转译）、后端不可达、参数缺失/格式错误、结果集超限、重名（DuplicateEntryError 409 转译）等（规范 §8.6、PRD §7、B01–B04）；
5. **幂等边界契约**：窗口期冻结值（create 组 300s、confirm/cancel 组 60s，E02 不得放宽）、指纹规则（server 依业务参数规范化、agent 不感知、传输/客户端字段不进指纹、同参同指纹异载异指纹）、误合并策略、confirm/cancel 状态断言兜底（幂等命中=返回幂等成功、非通用错误；具体返回结构由 D02 冻结，见 B05 §18.4 第 2 条）（B05 §18.3、PRD §5.1、规范 §9.3）；
6. **前置断言 / 事后校验 / 批次台账公共口径**：断言两层拆分（schema vs 业务状态）、校验两层拆分（返回值形状 vs 写后回读终态）、乐观版本断言口径（写 tool 必须携带 `modified`）、批次台账公共口径（批次标识、同批变更、回滚路径、`batch_status_get` 可见性边界）（规范 §9.4/§9.5/§9.6、PRD §5.2–§5.4、B01–B04）；
7. **窄接口与允许清单边界**：操作允许清单（12 类对象）与引用允许清单（9 类依赖对象）边界（清单外 MUST NOT 读写、引用清单只可引用不可增删改，PRD §2.3）、Link 字段目标仅限引用允许清单、禁止任意字段名/DocType、子表仅作父单据嵌套行、每个 tool 只暴露最小参数与动作且 description 声明窄接口边界（规范 §9.6、PRD §5.6）。

> 公共契约正文一经冻结，成为 D02 权威输入（E02 与本包共同对齐 B05 §18.3、保持一致，非本包下游）；修改须走变更控制（总则 §12）。D01 本身不改变 PRD 冻结语义。

## 10. 不变量

- 冻结 PRD、规范、总则、模板、登记表结构与边界规则内容不得被 D01 修改；
- 公共契约只含跨 tool 共享口径，不含任何具体业务 tool 的 name/schema/断言（不写死 #6–#26 逐 tool 契约）；
- 幂等边界与 B05 §18.3 一致：窗口期不得放宽、指纹由 server 规范化且 agent 不感知、传输/客户端字段不进指纹；
- 公共契约不得绑定具体传输层字段（`id`/`progressToken`/`claudecode/toolUseId` 等，规范 §9.3、B05 结论）；

- 人确认操作未经有效 server 侧确认不得写入（规范 §9.7）；
- 后端不可达时写操作不得自动重试（总则 §6.10）；
- 错误不得以成功响应伪装、失败路径不得静默成功（规范 §8.6/§9.5）；
- 不读取 C01a 题目正文、隐藏数据或终态断言；不接入、不改变 ERPNext 后端或任何数据库状态；
- 未经实测/未经上游冻结结论的表述不得写入公共契约（不得以推测代替结论）。

## 16. 风险、假设与待决事项

- **档位 1 验收边界**：D01 不设正式验收题、不强制独立验收，其正确性由 D02 首次使用时验证（总则 §7.1）。这要求 D02 冻结时逐条核对公共契约与实际 tool 契约的契合度，发现公共契约缺失/歧义即回退 D01 升版；
- **幂等边界依赖 B05 冻结值**：窗口期 300s/60s、指纹规则、confirm/cancel 状态断言均来自 B05 §18.3 已封存结论，D01 只落地为契约口径、不得反向放宽；若 E02 实现时发现该口径不可行，须走变更控制（总则 §12），不得在 D01 内静默调整；
- **乐观版本断言为跨 tool 硬口径**：B01–B04 实测一致结论「写 tool 必须携带 `modified` 做乐观并发，否则无并发保护」将作为公共契约的 MUST 级口径写入；但具体每个 tool 的 `modified` 语义由 D02 逐 tool 冻结；
- **错误模型依赖 B01–B04 错误事实**：DuplicateEntryError（409）、TimestampMismatchError（417）等后端原生错误的转译口径以 B01–B04 接口事实为准，D01 不重新实测；
- **C01a 隔离**：D01 只确认 C01a 完成及版本标识，不得读取候选正文/初始态/断言；C01a 候选落验收区，对本包实施主体不可读（边界 §3、总则 §13）；
- **不预写 E02**：D01 只冻结幂等/断言/批次的契约口径，不冻结实现手法；E02 的批次 Owner 持久化、跨会话查询授权等以 B00 身份结论为前提，由 E02 冻结（总则 §13）。
- **对齐点兜底**：D01 的契约口径（W05/W06）与 E02 的实现能力均源自 B05 §18.3、互不消费对方；若二者漂移，由 D02 冻结时逐 tool 核对为对齐点兜底——D02 同时消费 D01 公共契约、B05 幂等边界与 E02 实现能力。
