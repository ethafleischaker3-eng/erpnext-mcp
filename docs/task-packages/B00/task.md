## 2. 目标

完成后端基础能力准备，产出可复核的实测记录，冻结以下事实并作为 A01 及后续任务的权威输入：

1. **对象裁剪**：12 类操作对象 + 9 类引用对象 + 子表边界的 DocType 在后端真实存在且可访问，清单外对象不纳入；
2. **权限模型可行性**：确认后端可按调用方粒度（系统用户 + 角色）配置最小权限，并建立核查/探针所需的临时最小权限（不形成最终业务权限）；
3. **原生 API 基础可用性**：确认 12 类操作对象与 9 类引用对象 DocType 存在且只读可达，写端点以最小合成探针验证可用；
4. **事务与回滚基础**：确认后端具备事务与回滚能力、写入失败不静默成功，环境具备执行原子性测试的条件；
5. **快照重置**：确认数据库可重置到指定快照；
6. **独立验收环境**：确认 `erpnext.local` 为独占、非生产的本地验收站点；应用版本符合冻结目标 `15.121.2`/`15.120.1` 且迁移状态正常，为 12+9 对象生成 schema/元数据基线哈希作为目标 schema 基线（尚未与未来生产环境做等同性比较，部署前须另行比对）；建立初始快照与重置脚本；
7. **可信调用方身份基础**：确认认证主体标识来源、跨会话稳定性、server 可信获取方式、服务账号共享策略及管理员/普通调用方区分原则；
8. **币种与默认价格表**：重新验证并冻结 Company `gjg` 唯一、`default_currency`=CNY、selling 价格表唯一=Standard Selling 及对应 fail-closed 条件；
9. **实施区/验收区隔离**：填写实际路径、明确 Owner，建立独立受限 Windows 账户 + NTFS ACL 的真实文件系统权限隔离，使实施主体读取隐藏验收材料得到 Access Denied（P00 遗留交付物）。
