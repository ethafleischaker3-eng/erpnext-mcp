## 2. 目标

在不接入 ERPNext 后端、不改变任何数据库状态的前提下，用隔离的最小重试/关联探针，实测目标客户端、MCP SDK 与传输方式对 `tools/call` 的自动重试与请求关联行为，产出可复核的幂等可实现性调研结论并冻结，作为 E02、D01/D02 的权威输入。结论必须逐项覆盖 PRD §5.1「B05 必须形成的证据与决策」（第 214–220 行）的五条要求（展开为以下 10 项）：

1. **被测对象事实**：目标客户端名称 + 精确版本 + 传输方式（复用 A01 §18 已封存事实：Claude Code 2.1.263 / MCP 2025-11-25 / stdio，L3 成立）；钉定 `tools/call` 请求-响应链路上的 MCP SDK（含更高层 Agent/harness 承载层）精确版本；
2. **重试行为实测**（PRD §5.1 第 216 行）：实测目标客户端、MCP SDK 与传输方式是否自动重试 `tools/call`，以及超时、断线、重连三种场景下的行为；逐层区分「传输/SDK 层透明重试」「客户端/harness 层重试」「模型/agent 层重新发起 tools/call」三层，记录各自证据；
3. **关联信号判定**（PRD §5.1 第 217 行）：确认是否存在可被 server 可信观察、且不由 agent 伪造的关联信号，并判断该信号是否违反「不绑定特定传输层字段」的上游约束（规范 §9.3）；逐候选信号（JSON-RPC `id`、`_meta`、`progressToken`、stdio 进程/连接身份、会话、时序）判定「server 可观察性 / agent 可伪造性 / 违反 §9.3 / 跨重试可关联性」；
4. **分叉决策**（PRD §5.1 第 218 行）：存在合规可信信号 → 冻结其生命周期及「同一业务意图」的判定边界；不存在 → 必须在业务引用号、误合并策略、窗口期缩短或其他业务层方案中作出明确选择并记录残余风险；
5. **指纹不可覆盖结论**（PRD §5.1 第 219 行）：agent 传入的随机 request id 或幂等键不得成为可信覆盖值；有效负载不同不得命中同一指纹（相同业务参数 → 相同指纹、不同有效负载 → 不同指纹）；
6. **窗口期冻结值或替代方案**（PRD 决议 10、§5.1 表格「窗口期」列）：给出可复核的窗口期冻结值（或明确业务层方案替代/缩短窗口期）及依据；24h/1h 仅为调研初始假设，不构成本版冻结契约；
7. **「同一业务意图连续调用只变更一次」的可执行验收方法**（PRD §5.1 第 220 行，规范 §12.3 幂等冲突类失败路径题）；
8. **「合法重复业务如何表达」的可执行验收方法**（PRD §5.1 第 220 行，独立合法重复业务不得被幂等机制误合并）；
9. **残余风险与已知限制**：逐项记录无法消除的误合并风险、窗口期暴露面及其适用边界；
10. **结论由接入方 gjg 确认有效**（PRD 决议 10；总则 §4.2 调研输出必须是可复核实测记录）。

调研结论为冻结输出，其内容结构见第 9 节，是 E02、D01/D02 的权威输入；探针本身与探针运行结果不构成任何正式业务 tool 或业务 tool 验收依据（总则 §16.1）。B05 结论形成前，E02 不得冻结或实施（总则 §13、§16.2）。

- 读取过隐藏验收材料的人员、会话或执行实例不得参与对应实现、实施方案评审、调参或定向修复；

- 不得接入或改变 ERPNext 后端（数据库、REST API、bench、站点数据）；
- 不得将 agent 传入的随机 request id 或幂等键视为可信覆盖值、不得让其参与或覆盖 server 生成的幂等指纹（规范 §9.3；PRD §5.1 第 219 行）；
- 不得在 B05 结论冻结前，擅自用会话、请求 ID 或传输层字段代替「同一业务意图」判定规则（总则 §6.10）；
- 不得将 B05 状态误作 E02 冻结、业务 tool 实现或项目完成状态。

## 9. 输入输出契约

B05 不提供正式业务 tool，不定义业务 tool 语义或 schema。本节规定两件事：(a) 探针 tool 的临时契约；(b) 调研结论的冻结输出结构（下游权威输入）。

### 9.1 探针 tool 临时契约（仅能力调研，非业务 tool）

| 项 | 规定 |
|---|---|
| 探针 server | 隔离 MCP server，位于 `docs/task-packages/B05/probe/`；声明 `tools/call` 能力；不接入 ERPNext |
| 探针 tool 名 | `probe_retry_write`（能力调研用临时命名，不得使用 `erpnext_*` 前缀，不得复用为正式业务 tool） |
| 业务语义 | 模拟一次写动作：收到调用 → 按注入的故障模式执行（normal 写标记返回成功 / slow 延迟超时 / crash 崩溃断线 / error 返回业务错误）→ 记录到达 |
| 故障注入 | 由控制文件或环境变量设定下一调用的故障模式，实施时择一并记录；探针在每次 `tools/call` 到达后、执行故障前，先将到达日志（时间戳、JSON-RPC `id`、payload 指纹、连接/进程身份、`_meta`/`progressToken` 存在性）落盘 flush |
| annotation | 显式声明：只读=否、破坏性=是、幂等性按探针实现如实声明、是否与外部世界交互=否（§8.1） |
| 输入 | 合成业务参数（目标对象标识 + payload），不含任何真实业务数据或真实凭据 |
| 副作用 | 仅写/清本地合成标记文件 `docs/task-packages/B05/probe/state/`，不涉数据库、不涉 ERPNext |
| 会话/重连观测 | 探针在 `initialize` 握手与进程启动时记录事件（协议版本、capabilities、进程 pid），用于观测断线重连是否产生新会话/新握手 |
| 敏感凭据场景 | 以占位/合成值核查；探针不索取真实敏感凭据 |

### 9.2 调研结论输出契约（冻结输出，下游权威输入）

调研结论（交付物 D05）必须逐项包含并可复核：

1. 被测客户端/SDK/传输方式事实（名称 + 精确版本 + 传输方式 + MCP 协议版本 + MCP SDK/harness 承载层精确版本）；
2. `tools/call` 重试行为结论：超时、断线、重连三种场景下，逐层（传输/SDK 层、客户端/harness 层、模型/agent 层）是否自动重试、重试是否复用相同 JSON-RPC `id`、重试 payload 是否一致、是否可被 server 关联（证据引用）；
3. 关联信号判定矩阵：候选信号 × {server 可观察性 / agent 可伪造性 / 违反 §9.3 / 跨重试可关联性}（证据引用）；
4. 合规可信信号结论（分叉）：存在 → 冻结其生命周期与「同一业务意图」判定边界；不存在 → 业务引用号/误合并策略/窗口期缩短等业务层方案的明确选择 + 残余风险记录；
5. 幂等指纹不可覆盖结论：指纹 = server 依业务参数规范化计算、agent 不感知；agent 传入的随机 request id 或幂等键不得成为可信覆盖值；有效负载不同不得命中同一指纹（证据引用）；
6. 窗口期冻结值或替代方案：给出可复核的窗口期冻结值（或明确业务层方案替代/缩短窗口期）及依据；24h/1h 仅为调研初始假设；
7. 「同一业务意图连续调用只变更一次」的可执行验收方法（可写成终态断言）；
8. 「合法重复业务如何表达」的可执行验收方法（独立合法重复业务不被误合并的验收断言）；
9. 残余风险与已知限制（逐项记录）；
10. 接入方（gjg）确认有效的签署记录。

调研结论一经冻结，写入符合性材料或成为 E02、D01/D02 权威输入时均须走变更控制；B05 本身不改变 PRD 冻结语义。

## 15. 停止与升级条件

继承《MCP 改造任务包总则》第 6.15 节。另有以下 B05 条件时，停止受影响工作并转为「待澄清」：

## 16. 风险、假设与待决事项

- 目标客户端为 A01 §18 已封存事实（Claude Code 2.1.263 / MCP 2025-11-25 / stdio，L3 成立）；更换客户端（含 VS Code 扩展，已知静默拒绝 elicitation 的 issue claude-code#41292）须重新起算核查（总则 §12）；
- MCP 协议版本、MCP SDK 精确版本、harness 承载层（Claude Agent SDK / Claude Code）待实施 W01/W02 钉定；重试行为以接入时协议版本文档与 SDK 源码为准，本包不预绑定具体字段名或假设某层必然重试；
- **核心难点（三层重试区分）**：传输/SDK 层「透明重试」可能保留协议层关联（复用相同 JSON-RPC `id` 或明确 retry 语义），而模型/agent 层「重新发起 `tools/call`」对 server 而言是全新请求、可能无协议层关联、与合法重复业务不可区分——这正是「无可信信号」分支的根源，W04–W06 必须逐层取证，不得将模型层重试误判为传输层透明重试，也不得将传输层行为外推到模型层；
- 窗口期 24h/1h 仅为 PRD §5.1 调研初始假设，不构成本版冻结契约；B05 必须给出可复核的冻结值或明确业务层方案替代并记录残余风险（CHG-20260912-001）；
- 探针依赖（MCP SDK）是否已存在于环境待实施时确认；优先复用，否则在探针目录内隔离引入或手写最小 stdio/JSON-RPC 服务，不改变项目/后端依赖（§6.3）；
- B05 不接入 ERPNext 后端、不涉数据库，因此无需 B00 的站点快照/重置能力；探针副作用仅为本地合成标记，可完全清除；
- 探针及其结果不得被后续 E/F 包复用为业务 tool 或业务 tool 验收依据（总则 §16.1）；重试/关联调研与正式业务 tool 验收是两件事；
- Implementer 为独立编码上下文，Acceptor=gjg、Implementation Reviewer=gjg；实施会话与 Acceptor 的隔离沿用 B00 已建立的隔离事实（受限账户 + NTFS ACL），B05 不重复建设；
- 调研结论一旦冻结即纳入 E02、D01/D02 权威输入，后续修改须走变更控制（总则 §12）。
