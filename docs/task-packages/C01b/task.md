## 2. 目标

在验收区，以 C01a 的候选三段式骨架为种子，以冻结 D02 契约、D01 公共契约、B01–B04 接口事实、B05 幂等边界及 PRD §1.3/§6 与规范 §12.3/§13 为权威口径，完成：

1. **tool 覆盖映射**：把每道候选/补题映射到 D02 冻结的 26 个 tool，形成覆盖矩阵，识别覆盖缺口；
2. **精确终态断言补齐**：把三段式「断言骨架」补齐为字段级可判定的精确终态断言（依据 B01–B04 接口事实复核字段名，不越出 C01a object-scope 名单）；
3. **初始数据与重置**：为每题定义合成初始数据（快照）与重置脚本（基于后端原生备份/恢复能力，PRD §5.7）；
4. **L3/L2 验收矩阵**：按 PRD §1.3 冻结 L3 与 L2 受限形态两套验收口径（不共用同一写入终态断言）；
5. **每题调用与自纠上限**：按 PRD §6「可复算口径」第 4 条「轮次合理」为每题冻结最大 tool 调用次数与允许自纠次数；
6. **可解性验证**：逐题验证「用冻结 26 tool 契约 + 接口事实可解」，无契约缺口；发现缺口则回 D02 走变更控制；
7. **覆盖缺口补题**：覆盖不满下限时，启动新盲出题轮次补题（补题会话与 C01a 同盲隔离）；
8. **任务集最终冻结**：冻结任务集迁入 `D:\second-acceptance\task-sets\`，产出 Evidence Manifest。

## 9. 输入输出契约

C01b 不定义可调用 tool 契约（不适用）。本节规定冻结任务集的输出结构（它是 E01、F01/F02/F04 与 G01 的权威验收输入）：

每题冻结结构（`task-sets/` 中每道题）必须包含并可复核：

1. **题号与形态归属**：稳定编号；L3 或 L2 受限形态（或双形态断言，PRD §1.3「不共用同一写入终态断言」）；
2. **初始数据状态**：合成数据定义（对象、字段、初始值），忠实 object-scope 名单与冻结价格表/币种事实（PRD 决议 2：公司 `gjg`、CNY、Standard Selling）；
3. **自然语言指令**：业务任务描述，不用 ERPNext 专有名词；
4. **精确终态断言**：字段级可判定（哪些记录的哪些字段变成什么；L3 断言最终单据/库存/流水，L2 断言完整方案 + 数据库全程零写入），非 agent 自评；
5. **快照与重置脚本**：该题初始态快照 + 重置脚本（PRD §5.7）；
6. **覆盖映射**：该题覆盖的 tool 编号与档位；
7. **调用与自纠上限**：最大 tool 调用次数 + 允许自纠次数（PRD §6「可复算口径」，验收时不得临时调整）；
8. **失败路径类别**（若为失败路径题）：参数缺失 / 前置断言不通过 / 幂等冲突 / 越权 / 声明与实现不一致 之一。

覆盖下限（MUST，规范 §12.3 + PRD §1.3）：
- L3：每个写操作 tool ≥1 题（读 tool 不设下限 SHOULD 覆盖）；三个启用档位（全自动 / 人确认 / 只出 plan）各 ≥1 题；
