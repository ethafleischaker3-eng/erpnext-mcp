## 2. 目标

在验收区，以 C01b 冻结的 **15 题任务集（T01–T15）+ 隐藏精确断言**为唯一验收口径，对 26 个 tool 的 MCP server（`server/index.js`）做**真实集成验收**，完成：

1. **逐题实跑**：对每一题执行「恢复干净基线快照 → 启动 server → 以被测 agent 跑题（含自纠）→ 以系统与数据库终态核对精确断言」，不以 agent 自评代替终态判定；
2. **次数核算**：记录每题实际 tool 调用次数与自纠次数，与 C01b 冻结上限比对，判定是否超限（超限即判不通过，验收时不得临时调整）；
3. **全量判定**：15 题（覆盖 26 tool：写 19/19、读 6/6、只出 plan 1/1；失败路径五类各 ≥1；销售/采购多步链各 ≥1）**连续两轮**全部通过 → G01 判定「通过」；
4. **失败归责**：任一题失败，归入「实现缺陷 / 契约冲突 / 测试集问题 / 环境问题」之一，分别走退回或变更控制，**禁止定向修复**；
5. **交付结论**：产出集成验收报告与 Evidence Manifest，作为项目完成门槛（总则 §16.4）与 H01 的权威输入。

## 3. 非目标

- 不以 agent 自评、单条日志或后端返回文案作为终态通过依据。

## 8. 验收方法与判定标准

### 8.1 逐题执行方法

对每一题 T01–T15，按以下顺序执行（总则 §10.2：以系统与数据库终态为准，不接受 agent 自评）：

1. **恢复快照**：以 C01b 冻结的该题初始快照/重置脚本（或统一基线 `clean-post-E01.sql`）恢复后端到该题初始态；确认恢复零残留；
2. **启动 server**：确认 MCP server（`server/index.js`，26 tool）与后端容器 `frappe_docker-backend-1`/`frappe_docker-db-1` 就绪，记录被测版本基线；
3. **跑题（含自纠）**：以被测 agent（含 L3 确认能力）按该题冻结的自然语言指令执行，允许在冻结自纠次数上限内自纠；记录完整 tool 调用序列；
4. **终态核对**：以系统与数据库终态核对该题精确断言（哪些记录的哪些字段变成什么），字段名溯源 D02 契约 + B01–B04 接口事实；判定通过/不通过；
5. **次数记录**：记录该题实际 tool 调用次数与自纠次数，与冻结上限比对；
6. **结论记录**：写入 `runs/`（通过/失败 + 失败归责类别 + 证据引用）；
7. **连续两轮复跑**：同一冻结任务集（15 题）在相同环境与版本基线下**连续执行两轮**，两轮分别独立恢复快照、分别判定，第二轮作为第一轮通过后的可复现性复核。

### 8.2 调用/自纠次数核算

- C01b 已为每题冻结「最大 tool 调用次数」与「允许自纠次数」（PRD §6 可复算口径）；
- 验收时不得临时调整上限；任一题实际调用次数或自纠次数**超过冻结上限，即判该题不通过**，即使终态断言满足；
- 次数核算对象为被测 agent 在跑题过程中实际发起的 tool 调用（含失败重试），口径以 C01b 冻结评分规则为准。

### 8.3 判定标准

- **通过判定**：同一冻结任务集（15 题）**连续两轮**均全部通过（每题终态断言全满足、调用/自纠次数未超限），且失败路径五类（参数缺失 / 前置断言不通过 / 幂等冲突 / 越权 / 声明与实现不一致）各 ≥1 题、销售/采购多步链各 ≥1 题**两轮均**全部通过，则 G01 判定「通过」（PRD §6 验收线「同一冻结任务集连续两轮 ≥ 90%」、§1.3 #4「失败路径题通过率 100%」；G01 以 15 题全过为更严口径，但不得以单轮全过替代「连续两轮」稳定性要求，对齐总则 §16.4「冻结任务集连续达到 PRD 指标」）。
- **失败归责**：任一题失败，必须归入以下四类之一（对应总则 §11 五类归因），不得静默跳过：

| 归责类别 | 含义 | 处置路由 | 责任方 |
|---|---|---|---|
| 实现缺陷 | 实现不符合冻结契约（含未达 PRD 指标） | 退回对应 F/E 包（总则 §11 第1类、§14） | 对应实现包，未读题上下文修复 |
| 契约冲突 | ① tool 契约不足以支持真实业务任务；② 上游 PRD/规范冲突 | ① 回 D02 走变更控制（总则 §11 第2类、§12）；② 升级上游（PRD/规范）Owner 处置（总则 §11 第5类、§12） | ① D02 Owner；② 上游 Owner |
| 测试集问题 | 验收题违反后端实际业务语义 | 回 C01b 修题，升版并废止旧结果（总则 §11 第4类、§12） | C01b（Owner 拍板） |
| 环境问题 | 环境或初始数据不正确 | 修复环境/快照后重跑该题（总则 §11 第3类） | G01 执行者（不涉及归责） |

- **禁止定向修复**：G01 执行者读题后不得回头改 server 代码或为通过验收而调参/改题；失败只能记录 → 归责 → 退回。禁止通过降低断言、改写题目、临时放宽上限或手工改库来规避失败（总则 §4.5）。归责类别与处置路由的最终判定由 Owner 拍板，执行者只提供证据与初步归类。
